# Элементы

Все блоки, которые тема оформляет внутри статьи, по одному разу. `@primer/css`
покрывает большую часть того, что выдаёт Markdown; здесь собрано остальное — то,
что тема добавляет поверх, и то, что при её изменении легко сломать незаметно.
Оформление вокруг страницы и так есть на каждой странице.

Каждый тип блока-примечания — отдельный селектор в таблице стилей, поэтому
каждый псевдоним ниже получает собственный блок, а не строку текста: тип,
который никто не выписал, — это тип, пропажу которого никто не заметит.

<a id="admonitions"></a>

## Блоки-примечания

Расширение `admonition` выдаёт разметку без CSS, а в `@primer/css` тоже нет
правила для `.admonition`, так что всё, что ниже, — заслуга темы. Форма
повторяет оповещения GitHub: подкрашенный фон, цветная полоса слева, цветной
заголовок и октикон, соответствующий типу.[^alerts]

!!! note
    `note` получает акцентный синий Primer и октикон `info`. Встроенный код —
    `mkdocs.yml` — сохраняет собственный полупрозрачный фон, который ложится
    поверх подкраски, а не пробивает в ней серую дыру.

!!! tip
    `tip` получает зелёный цвет успеха и октикон `light-bulb`.

!!! hint "hint"
    Псевдоним `tip` с заголовком, заданным вручную, чтобы их можно было
    различить на этой странице.

!!! important
    `important` получает фиолетовый, который Primer называет «done», и октикон
    `report`.

!!! warning
    `warning` получает жёлтый цвет внимания и октикон `alert`.

!!! attention "attention"
    Псевдоним `warning`.

!!! caution "caution"
    Второй псевдоним `warning`.

!!! danger
    `danger` получает красный цвет опасности и октикон `stop`.

!!! error "error"
    Псевдоним `danger`.

!!! bug "bug"
    Второй псевдоним `danger`.

!!! example
    Тип, для которого у GitHub нет оповещения, сохраняет нейтральную заливку и
    нейтральную полосу и не рисует значка — ни цветного заголовка, ни пустого
    места там, где был бы значок.

!!! note "Собственный заголовок, с `code` внутри"
    Цвет типа подкрашивает весь заголовок, а на собственном фоне встроенного
    кода такое сочетание даёт контраст ниже 4.5:1 — поэтому код в заголовке
    остаётся цвета текста по умолчанию.

!!! warning "Блок с заголовком и пустым содержимым"

<a id="quotes"></a>

## Цитаты

> Цитата получает нейтральную заливку с половиной отступов блока-примечания:
> она должна читаться тише оповещения, а не как ещё одна его разновидность.
>
> Два абзаца — чтобы показать, что заливка заканчивается под последним из них,
> а не под первым.

<a id="code"></a>

## Код

Блоки кода подсвечивает Pygments, а цвета берутся из переменных `prettylights`
Primer, поэтому они следуют цветовому режиму. В углу каждого блока есть кнопка
копирования.

```python
from mkdocs_primer import __version__


def greet(name: str = "world") -> str:
    """Docstrings, keywords, strings and numbers all take separate colors."""
    return f"hello {name} from {__version__}"
```

Блок, строки которого длиннее колонки, прокручивается по горизонтали, а не
переносит строки и не растягивает страницу:

```console
$ mkdocs build --strict -f examples/rss/mkdocs.yml && mkdocs build --strict -f examples/gen-files/mkdocs.yml && mkdocs build --strict -f examples/diagrams/mkdocs.yml
```

Для diff-ов своё оформление. Следить стоит за заголовком фрагмента: это
единственное место, где подсветка отходит от палитры GitHub, потому что цвет,
который GitHub использует там, в тёмном режиме даёт контраст с фоном кода ниже
4.5:1.

```diff
--- a/mkdocs.yml
+++ b/mkdocs.yml
@@ -1,3 +1,3 @@
 theme:
-  name: mkdocs
+  name: primer
```

<a id="tables"></a>

## Таблицы

Primer чередует фон строк и выделяет заголовок; тема добавляет только одно —
поведение таблицы, которая не помещается. Если таблица шире колонки, она
прокручивается по горизонтали, а не растягивает страницу. А поскольку `table`
не получает фокус, тема делает её доступной по Tab, пока она переполнена, чтобы
до выступающей за край части можно было добраться без мыши. Длинная команда
выше оформлена точно так же и достаточно широка, чтобы это показать.

Поверхности на этой странице берутся из `@primer/primitives`, и именно поэтому
они следуют цветовому режиму без второго набора правил в теме:

| Токен | Светлая | Тёмная | Чем отображается |
| --- | --- | --- | --- |
| `--bgColor-default` | `#ffffff` | `#0d1117` | статья и страница за ней |
| `--bgColor-inset` | `#f6f8fa` | `#010409` | шапка и боковая панель |
| `--bgColor-muted` | `#f6f8fa` | `#151b23` | цитаты и блок-примечание без аналога в GitHub |
| `--bgColor-attention-muted` | `#fff8c5` | `#bb800926` | заливка под `!!! warning` |
| `--button-default-bgColor-rest` | `#f6f8fa` | `#212830` | карточки «Назад»/«Далее» под этой страницей |
| `--underlineNav-borderColor-active` | `#fd8c73` | `#f78166` | отметка текущей страницы в боковой панели |

<a id="definition-lists"></a>

## Списки определений

Расширение `def_list` принимает более простой синтаксис, чем HTML ниже:

`docs_dir`

:   Каталог, из которого MkDocs читает Markdown.

`site_dir`

:   Каталог, в который MkDocs записывает HTML.

Оба варианта доходят до Primer как один и тот же `<dl>`, поэтому они и
показаны вместе: правило, написанное для одного, применяется и к другому:

<dl>
<dt>Имя</dt>
<dd>Godzilla</dd>
<dt>Год рождения</dt>
<dd>1952</dd>
<dt>Место рождения</dt>
<dd>Япония</dd>
</dl>

<a id="images"></a>

## Изображения

Ширину колонки задаёт тема — `.primer-content` несёт ограничение, которое не
даёт тексту растянуться до 130 символов в строке, — поэтому изображение шире
этой колонки стоит иметь на странице. Оно должно уместиться в колонку, а не
раздвигать макет вбок.

Кроме того, это единственные изображения в содержимом сайта, а значит,
единственное, с чем может работать [mkdocs-glightbox](guide/plugins.md): нажмите
на одно из них, и оно откроется в лайтбоксе.

<a id="headings"></a>

## Заголовки

Из заголовков этой страницы строится оглавление в правой колонке, и у каждого
есть постоянная ссылка, которая появляется при наведении, — октикон, который
тема рисует поверх якоря, создаваемого расширением `toc`.

<a id="a-third-level"></a>

### Третий уровень

Вложенные заголовки в оглавлении сдвигаются вправо, поэтому этот стоит там
под пунктом **Заголовки**.

<a id="a-fourth-level"></a>

#### Четвёртый уровень

Достаточно глубоко, чтобы показать, что оглавление продолжает сдвигать пункты
и что у пункта такой вложенности в колонке всё ещё хватает места для текста.

[^alerts]: GitHub отображает собственные оповещения с классом `.markdown-alert`,
    который `@primer/css` не публикует, поэтому тема оформляет разметку
    `.admonition` расширения напрямую. Эта сноска заодно проверяет расширение
    `footnotes`.
