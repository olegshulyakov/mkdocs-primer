# Конфигурация

<a id="theme-options"></a>

## Параметры темы

| Параметр | По умолчанию | Описание |
|:---|:---|:---|
| `logo` | `null` | Изображение рядом с названием сайта; путь указывается относительно `docs_dir`. |
| `favicon` | `img/favicon.svg` | Значок сайта. |
| `icon` | `octicons` | Набор иконок для элементов управления темы: `octicons` или `lucide`. |
| `font.text` | `null` | Значение CSS `font-family` для интерфейса и текста. |
| `font.code` | `null` | Значение CSS `font-family` для встроенного кода и блоков кода. |
| `font.source` | `null` | URL внешней таблицы стилей или локальная таблица стилей в `docs_dir`. |
| `locale` | `en` | Язык собственных текстов темы. Каталоги поставляются для `en`, `es`, `fr`, `hi`, `pt`, `ru` и `zh`. |
| `direction` | `ltr` | Направление документа: `ltr` или `rtl`. |
| `include_sidebar` | `true` | Выводить боковую панель навигации. |
| `nav_expand` | `all` | Какие разделы навигации выводить вместе со страницами: `all` или `active` — только раздел текущей страницы и разделы без собственной страницы. На больших сайтах `active` уменьшает размер страниц и время сборки. |
| `show_footer` | `true` | Выводить подвал страницы. |
| `show_footer_generator` | `true` | Показывать в подвале «Сделано с помощью mkdocs-primer и MkDocs». |
| `social` | `[]` | Ссылки-иконки в подвале. |
| `show_metadata` | `true` | Выводить строку метаданных под заголовком страницы. |
| `show_metadata_created` | `true` | Показывать дату создания. |
| `show_metadata_updated` | `true` | Показывать дату последнего обновления. |
| `show_metadata_reading_time` | `true` | Показывать примерное время чтения. |
| `show_metadata_authors` | `true` | Показывать авторов. |
| `toc` | `auto` | Расположение «Оглавления»: `auto`, `expanded`, `collapsed` или `hidden`. |
| `offline` | `false` | Регистрировать service worker, который сборка сайта должна сгенерировать сама. |
| `color_mode` | `auto` | Начальная цветовая схема: `auto`, `light` или `dark`. |
| `light_theme` | `light` | Тема Primer для светлой схемы. |
| `dark_theme` | `dark` | Тема Primer для тёмной схемы. |

`color_mode` задаёт только *начальную* схему. Посетитель может сменить её переключателем в шапке, и его выбор сохраняется в `localStorage`.

`toc` определяет, куда попадёт оглавление, построенное из заголовков текущей страницы. `auto` кладёт его в правую колонку, если окну хватает ширины на третий столбец, а иначе — под заголовок страницы, где оно раскрывается по нажатию, а не стоит списком между заголовком и первым абзацем. `expanded` оставляет его в потоке текста и не пускает в колонку, `collapsed` превращает в раскрываемый блок, а `hidden` — или `false` — убирает совсем.

<a id="metadata-line"></a>

## Строка метаданных

Сразу под заголовком страницы, над текстом, тема может показать строку со сведениями о текущей странице: когда она создана, когда последний раз менялась, сколько времени займёт чтение и кто её написал. Каждый пункт появляется, только если включён его собственный параметр *и* для него есть данные, а вся строка не выводится, когда ни одному из четырёх пунктов нечего показать.

```yaml
theme:
  name: primer
  show_metadata: true # the line's own switch; false hides all four items
  show_metadata_created: true
  show_metadata_updated: true
  show_metadata_reading_time: true
  show_metadata_authors: true
```

`show_metadata` отключает всю строку независимо от параметров под ним. Каждый пункт можно отключить и по отдельности — например, если сайту нужны даты, но не оценка времени чтения.

`show_metadata_reading_time` оценивает время чтения в минутах по числу слов в отрисованной странице из расчёта 265 слов в минуту — средней скорости чтения взрослого человека. Для страницы без собственного содержимого, например индекса раздела, этот пункт не выводится.

Обе даты берутся из [mkdocs-git-revision-date-localized](https://github.com/timvink/mkdocs-git-revision-date-localized-plugin):

```yaml
plugins:
  - git-revision-date-localized:
      enable_creation_date: true # also required for the "created" date
```

Без этого плагина не появится ни одна из дат, а для даты создания нужен именно `enable_creation_date: true` — по умолчанию плагин её не выдаёт.

Авторы берутся из [mkdocs-git-authors](https://github.com/timvink/mkdocs-git-authors-plugin) и тоже не появляются, пока этот плагин не включён.

<a id="footer"></a>

## Подвал

Полоса внизу каждой страницы, под всем макетом. С одной стороны в ней две строки текста, с другой — ряд ссылок-иконок, а если положить в неё нечего, она не выводится вовсе. `show_footer: false` убирает её, как бы ни были настроены остальные параметры.

Каждая ссылка в подвале ведёт за пределы документации, поэтому все они открываются в отдельной вкладке.

Первая строка — копирайт и указание, где найти исходник страницы; о последнем см. раздел [Ссылки на редактирование](#edit-links). Копирайт — это собственный ключ MkDocs `copyright`, ключ верхнего уровня, а не параметр темы:

```yaml
copyright: Copyright &copy; 2026 Your Name
```

Вторая строка сообщает, чем собран сайт. Её отключает `show_footer_generator: false`:

```yaml
theme:
  name: primer
  show_footer_generator: false
```

<a id="social-links"></a>

### Ссылки на соцсети

`social` — это список ссылок, которые рисуются иконками напротив копирайта:

```yaml
theme:
  name: primer
  social:
    - service: github
      link: https://github.com/you/your-project
    - service: mastodon
      link: https://fosstodon.org/@you
      name: Follow the project on Mastodon
```

`service` называет один из логотипов, которые поставляются с темой. `name` необязателен: это доступное имя ссылки — то, что произносит экранный диктор, — и по умолчанию оно совпадает с названием сервиса, так что задавайте его всякий раз, когда одно слово «GitHub» не объясняет, куда ведёт ссылка.

Доступные сервисы:

`bitbucket`, `bluesky`, `codeberg`, `devdotto`, `discord`, `docker`, `facebook`, `forgejo`, `github`, `githubsponsors`, `gitlab`, `instagram`, `kofi`, `mastodon`, `matrix`, `medium`, `npm`, `opencollective`, `patreon`, `pypi`, `reddit`, `rss`, `stackoverflow`, `substack`, `telegram`, `twitch`, `x`, `youtube`, `zulip`.

Для всего остального укажите в `icon` путь к SVG в `docs_dir` вместо `service`:

```yaml
theme:
  name: primer
  social:
    - icon: img/linkedin.svg
      link: https://www.linkedin.com/company/your-company
      name: Your Company on LinkedIn
```

Такой логотип выводится как `<img>`, поэтому, в отличие от встроенных, сохраняет собственные цвета, а не подстраивается под окружающий текст. LinkedIn и Slack подключаются только так: обе компании попросили убрать их из набора иконок, на котором основана тема, поэтому ни одна из них в теме не поставляется.

Логотипы взяты из [Simple Icons](https://github.com/simple-icons/simple-icons) и распространяются под лицензией CC0-1.0. Изображённые на них бренды — нет: каждый остаётся товарным знаком своего владельца, и логотип в вашем подвале не означает ни связи с ним, ни его одобрения.

<a id="icons"></a>

## Иконки

Навигация в шапке, переключатель цветовой схемы, кнопка «Наверх» и кнопка копирования в блоке кода используют встроенные SVG из одного набора иконок. По умолчанию это `octicons`; чтобы выбрать иконки Lucide, укажите:

```yaml
theme:
  name: primer
  icon: lucide
```

Оба набора входят в тему, поэтому ни один из вариантов не добавляет запросов к CDN. Выбор набора влияет только на HTML-элементы управления темы. Переключатель языка всегда использует глобус из Octicons. Синтаксис иконок в Markdown и произвольные сторонние наборы иконок намеренно не поддерживаются.

<a id="fonts"></a>

## Шрифты

Шрифты подключаются только по желанию: по умолчанию тема не обращается к CDN шрифтов. Задайте семейства для текста и кода по отдельности, а затем укажите в `source` либо внешнюю таблицу стилей, либо CSS-файл в `docs_dir`:

```yaml
theme:
  name: primer
  font:
    text: 'Inter, sans-serif'
    code: '"JetBrains Mono", monospace'
    source: https://fonts.googleapis.com/css2?family=Inter:wght@400;600&family=JetBrains+Mono&display=swap
```

Для сайта, который всё размещает у себя, положите файлы шрифтов и таблицу стилей в `docs_dir` и укажите относительный путь:

```yaml
theme:
  name: primer
  font:
    text: 'Atkinson Hyperlegible, sans-serif'
    code: 'Atkinson Hyperlegible Mono, monospace'
    source: fonts/fonts.css
```

```css title="docs/fonts/fonts.css"
@font-face {
  font-family: "Atkinson Hyperlegible";
  src: url("AtkinsonHyperlegible-Regular.woff2") format("woff2");
  font-display: swap;
}
```

Браузер кеширует эти файлы как обычно. Собственный хостинг шрифтов избавляет от стороннего запроса и оставляет сайт рабочим без сети, когда его ресурсы уже в кеше.

<a id="language"></a>

## Язык

Собственные тексты темы — `Search`, `Back to top`, `Previous`/`Next`, подписи в подвале — берутся из каталога gettext независимо от языка, на котором написаны ваши страницы. Язык выбирается параметром `locale`:

```yaml
theme:
  name: primer
  locale: ru
```

Каталоги поставляются для `en`, `es`, `fr`, `hi`, `pt`, `ru` и `zh`. Неподдерживаемая локаль приводит к английскому языку, а не к ошибке сборки.

!!! note "Многоязычному сайту нужен `locale` для каждого языка"
    mkdocs-static-i18n выставляет `theme.locale` автоматически только для тем,
    которые поставляются с самим MkDocs, поэтому сторонней теме его нужно
    указать явно. Добавьте его к каждому языку, иначе на всех локалях
    интерфейс темы будет на английском:

    ```yaml
    plugins:
      - i18n:
          languages:
            - locale: en
              default: true
              build: true
              theme:
                locale: en
            - locale: ru
              build: true
              theme:
                locale: ru
    ```

!!! warning "Ставьте язык по умолчанию последним"
    Плагин выполняет по одному проходу сборки на каждый язык, а страницы,
    которые существуют на весь сайт в одном экземпляре, — `404.html` и
    `search.html` — перезаписываются каждым проходом. Поэтому они оказываются
    на языке, указанном **последним**. Поставьте язык по умолчанию в конец
    списка, чтобы они вышли на нём. Переключатель языка тема сортирует сама,
    так что порядок, который видят посетители, от этого не меняется.

Чтобы добавить или исправить перевод, отредактируйте `mkdocs_primer/locales/<locale>/LC_MESSAGES/messages.po` и перекомпилируйте каталог — см. [`RELEASING.md`](https://github.com/olegshulyakov/mkdocs-primer/blob/main/RELEASING.md).

<a id="right-to-left-layouts"></a>

## Макеты справа налево

Для документа с письмом справа налево задайте `direction: rtl`. Тема ставит `dir="rtl"` на корневой элемент HTML и с помощью логических CSS-свойств зеркально отражает шапку, боковую панель, мобильную навигацию, постраничную навигацию, подвал, меню и элементы управления. Код и диаграммы намеренно остаются слева направо.

```yaml
theme:
  name: primer
  direction: rtl
```

Направление задаётся для всего сайта; тема не выводит его из локали страницы или языка.

!!! warning "`light_theme` и `dark_theme` пока принимают только `light` и `dark`"
    Primer публикует четырнадцать тем (`dark_dimmed`, `light_high_contrast`,
    `dark_tritanopia` и другие), но эта тема поставляет цветовые токены только
    для двух из них — полный набор добавил бы заметно больше мегабайта CSS.
    Если указать любую другую тему, страница отрисуется вовсе без цветов, а не
    с ошибкой. Поддержка других тем запланирована на будущее.

<a id="heading-anchors"></a>

## Якоря заголовков

Чтобы рядом с каждым заголовком при наведении появлялся якорь, как на GitHub, включите расширение `toc` с постоянной ссылкой перед заголовком, у которой есть класс Primer `anchor`:

```yaml
markdown_extensions:
  - toc:
      permalink: ""
      permalink_class: anchor
      permalink_leading: true
      permalink_title: Permanent link
```

Октикон тема рисует сама, поэтому `permalink` задан пустой строкой, а не привычным `true`. Дело не только во внешнем виде: плагин поиска MkDocs не вырезает символы постоянных ссылок, так что иначе в результатах поиска появлялся бы `¶`.

Без этой настройки постоянная ссылка всё равно работает, просто выглядит как обычный символ, а не октикон.

<a id="syntax-highlighting"></a>

## Подсветка синтаксиса

Цвета кода берутся из переменных Primer `prettylights`, поэтому автоматически следуют текущей цветовой схеме. Выбирать стиль Pygments не нужно:

```yaml
markdown_extensions:
  - pymdownx.highlight
  - pymdownx.superfences
```

Оформлены обе обёртки, `.highlight` и `.codehilite`, так что `codehilite` тоже работает.

Тема добавляет кнопку копирования в каждый блок Pygments `.highlight`. Она копирует видимый исходный код и сообщает, удалось ли записать его в буфер обмена. Блоки, которые отрисовывают плагины, например Mermaid и Vega-Lite, намеренно исключены.

<a id="navigation-controls"></a>

## Элементы навигации

Когда страница прокручена на 400 пикселей, в её правом нижнем углу появляется кнопка «Наверх». Она возвращает посетителя к началу документа и переводит фокус клавиатуры на ссылку с названием сайта. Если посетитель запросил уменьшение анимации, переход происходит мгновенно.

<a id="offline-support"></a>

## Работа без сети

`offline: true` добавляет на каждую страницу одно: скрипт, который регистрирует `service-worker.js` из корня сайта. Сам этот файл тема не пишет, и в MkDocs нет ничего, что бы его создало, — генерировать его должна ваша собственная сборка отдельным шагом после `mkdocs build`:

```yaml
theme:
  name: primer
  offline: true
```

```console
$ mkdocs build
$ npx workbox generateSW workbox-config.cjs
```

Именно service worker заранее кеширует собранный сайт, так что посетитель, который однажды на нём побывал, сможет читать его снова без сети. Если оставить `offline` равным `false`, регистрация не выводится — это и нужно сайту без такого шага сборки: страница, которая запрашивает никем не сгенерированный `service-worker.js`, при каждом посещении записывает в консоль ошибку 404.

Две вещи ему не под силу. Браузеры не разрешают service worker вне безопасного контекста, поэтому сайт нужно отдавать по HTTPS или с `localhost`; папка, открытая через `file://`, от всего этого работать без сети не станет. И предварительное кеширование срабатывает со *второго* посещения — первое как раз заполняет кеш.

Полный рабочий пример — собственные `workbox-config.cjs` и `npm run build:offline` этого репозитория.

<a id="markdown-extensions"></a>

## Расширения Markdown

Ни одно из них не обязательно, но в теме есть оформление, которое проявляется, только когда они включены:

```yaml
markdown_extensions:
  - admonition   # !!! note blocks, colored with Primer's alert palette
  - def_list
  - footnotes
  - tables
  - pymdownx.highlight
  - pymdownx.superfences
  - pymdownx.tilde
```

Отдельно стоит сказать про `admonition`: расширение выдаёт разметку без собственного CSS, и в `@primer/css` для неё тоже нет правил, поэтому блоки-примечания без оформления — частый сюрприз. Тема восполняет этот пробел — см. [примеры](../elements.md#admonitions).

<a id="custom-css-and-javascript"></a>

## Собственные CSS и JavaScript

`extra_css` подключается после всех таблиц стилей темы, поэтому ваши правила побеждают без `!important`:

```yaml
extra_css:
  - css/overrides.css
extra_javascript:
  - js/site.js
  # MkDocs 1.5+ also takes the mapping form.
  - path: js/chart.js
    type: module
```

Что туда писать, рассказывает страница [Стилизация](../styling.md): собственные переменные макета темы, а также почему переопределение цветового токена Primer в `:root` отбрасывается, а то же правило под двумя селекторами атрибутов применяется.

`extra_javascript` выводится в конце `<body>`, после собственных скриптов темы.

!!! note "Плагины, которые сами подключают свои ресурсы"
    Плагин, который вписывает теги `<link>` прямо в HTML страницы, а не
    добавляет их в `extra_css`, — например, mkdocs-glightbox — оказывается
    *после* ваших переопределений. Оформляйте такие элементы более
    специфичным селектором, а не полагайтесь на порядок.

<a id="edit-links"></a>

## Ссылки на редактирование

Когда заданы `repo_url` и `edit_uri`, [подвал](#footer) ссылается на исходный файл текущей страницы:

```yaml
repo_url: https://github.com/you/your-project
edit_uri: edit/main/docs/
```

Если задан `repo_url`, но не `edit_uri`, ссылку на отдельную страницу построить не из чего, и вместо неё подвал называет репозиторий — так читатель всё равно найдёт исходники с любой страницы сайта.
