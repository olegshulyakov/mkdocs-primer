# Стилизация

Таблицы стилей подключаются к странице в фиксированном порядке: токены дизайна
из `@primer/primitives`, `@primer/css` от GitHub, цвета Pygments, собственный
`theme.css` темы и последним — всё, что указано в `extra_css`. Именно то, что
ваши правила идут последними, позволяет им побеждать без `!important`, но только
против правил того же веса, и здесь кроется единственная настоящая ловушка на
этой странице.

Действуйте в таком порядке: сначала [опция темы](guide/configuration.md), если
она покрывает задачу, затем переменная ниже, затем токен Primer и только потом
собственное правило для разметки.

<a id="the-themes-layout-variables"></a>

## Переменные макета темы

Эти пять переменных объявляет тема в `:root`, и они предназначены для того,
чтобы их задавали:

| Переменная | По умолчанию | Что она определяет |
| --- | --- | --- |
| `--primer-sidebar-width` | `288px` | колонку навигации вместе с её отступами |
| `--primer-rail-width` | `256px` | третью колонку, если окну хватает для неё места |
| `--primer-article-max` | `720px` | максимальную ширину текста |
| `--primer-gutter` | `var(--base-size-16)` | расстояние от края окна и от навигации |
| `--primer-header-height` | `56px` | высоту шапки и то, на сколько отступают закреплённые колонки |

Достаточно блока `:root` в вашей таблице стилей, поскольку больше их нигде не
объявляют:

```css
/* docs/css/overrides.css, named in extra_css */
:root {
  --primer-article-max: 880px;
  --primer-sidebar-width: 240px;
}
```

Ширины, при которых макет меняет форму, в их число не входят: боковая панель
становится колонкой при 1012px, а оглавление переходит в правую колонку при
1280px. Оба значения записаны в медиазапросах, а медиазапрос не может читать
пользовательское свойство. Поэтому, сузив боковую панель, вы сделаете её уже,
но не заставите появиться раньше.

<a id="primers-tokens"></a>

## Токены Primer

Цвета, размеры и шрифты берутся из `@primer/primitives`, включённого в пакет в
`mkdocs_primer/css/vendor/`. Имена и их значения принадлежат Primer, и искать
их стоит в [его документации](https://primer.style/product/primitives/);
на странице [Элементы](elements.md) показано несколько поверхностей этого сайта
и то, каким токеном окрашена каждая.

При переопределении токена правила порядка уже недостаточно:

```css
/* Does nothing. */
:root {
  --fgColor-default: #24292f;
}

/* Works. */
[data-color-mode][data-light-theme] {
  --fgColor-default: #24292f;
}
```

Каждый цветовой токен объявлен для пары селекторов атрибутов —
`[data-color-mode="light"][data-light-theme="light"]` и её вариантов: так одна
таблица стилей вмещает оба цветовых режима. Эта пара специфичнее `:root`, какой
бы файл ни шёл последним, поэтому переопределение в `:root` молча отбрасывается.
Укажите те же два атрибута — и порядок снова решает, теперь в вашу пользу.

С размерами и типографикой иначе: `primitives-base.css` объявляет их в `:root`,
поэтому `--base-size-16` и подобные переопределяются обычным `:root`.

Сменить всю палитру разом через `light_theme` или `dark_theme` сейчас нельзя:
тема включает токены только для `light` и `dark`, о чём предупреждает
страница [Конфигурация](guide/configuration.md).

<a id="what-not-to-reach-for"></a>

## Чего не стоит трогать

Имена классов `primer-*` — это то, как таблица стилей обращается сама к себе, а
не публичный интерфейс. Их переименовывают и меняют назначение при каждом
изменении макета: в недавних выпусках `.primer-toc-summary` переехал с
`<summary>` на кнопку, изменилось то, что помечает `.primer-nav-section-label`,
а с переключателя языка убрали `.btn-octicon`. Если вы пишете собственное
правило для одного из этих классов, стоит закрепить версию темы.

Ещё две переменные темы — это флаги, а не настройки. `--primer-toc-rail` —
то, через что таблица стилей сообщает скриптам, достаточно ли широко окно для
правой колонки, а `--primer-nav-depth` — уровень вложенности, который шаблон
навигации ставит на каждую строку, чтобы по нему рассчитывался отступ.
Если задать любую из них снаружи, ничего не включится; это лишь собьёт с толку
код, который её читает.

Чтобы управлять цветовым режимом из скрипта, а не стилями, используйте событие
`primer:color-mode-change`, которое тема отправляет на `document`; его
использует [пример с диаграммами](examples.md) для перерисовки.
